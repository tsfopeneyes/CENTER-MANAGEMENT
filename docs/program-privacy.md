# 모집 전 본문 보호 운영 메모

## 2026-08-31 후속 요청 — 카드 정보 공개 범위 확장 (운영 반영)

사용자가 모집 예정 카드의 이미지·짧은 소개·장소·정원 공개를 승인했다.
`20260831010300_publish_program_card_metadata.sql`은 기존 공개 뷰의 뒤에 해당 필드만 추가한다.
본문·신청 질문·임의 JSON은 계속 제외하고, 비공개 글 제외와 원본 행 접근 제한도 유지한다.
원본 데이터·인증 구조·로그를 바꾸지 않는다. 알림 활성화 승인에 따라 이 후속 SQL과 화면을 운영 반영했다.
이하 운영 기록은 최초 적용 당시의 공개 범위다.

2026-08-31 사용자 승인으로 `20260831010200_protect_unpublished_programs.sql`을 운영 적용했다.
사이트·서버 함수 배포는 하지 않았다. 기존 본문을 이동하거나 지우지 않았다.

## 접근 범위

- 익명/일반 사용자: 시작 일시가 설정된 신청 프로그램의 모집 시작 전 원본 및 미작성 원본을 조회할 수 없다.
- 공개 일정 목록: 명시된 제목·날짜·상태·지역 필드만 제공한다. 본문, 이미지, 소개, 장소, 신청 질문은 없다.
- 모집 시작 후 준비 완료: 같은 원본 행을 서버 시각으로 공개한다. 주기적인 DB 갱신이나 본문 복사는 없다.
- 기존 프로그램: 시작 NULL은 기존 읽기/쓰기 방식을 유지한다. 시작 시각을 추측해 이관하지 않는다.
- 관리자: `calendar_private.admin_identities`의 검증된 인증 ID로 읽기/편집한다.
  이 목록은 기존의 넓은 프로필 수정 권한과 분리했다. 브라우저가 프로필 역할이나 인증 연결을 바꿔도 권한이 생기지 않는다.

## 관리자 권한 유지

현재 관리자 프로필 22개에 대응하는 Supabase 인증 ID 23개를 등록했다.
앞으로 관리자 추가/해제 시에는 서버 관리자가 실제 인증 ID를 확인한 뒤 이 목록도 등록/해제해야 한다.
`calendar_private`는 공개 API 스키마가 아니며 익명/일반 인증 사용자에게 접근권한을 주지 않는다.
서비스 역할 또는 관리 SQL 연결로만 변경한다. 프로필의 `role` 수정만으로 본문 접근권한을 부여하지 않는다.

## 남은 인증 위험

기존 회원 테이블은 광범위한 공개 읽기/쓰기가 가능하고 현재 로그인 화면은 회원 정보의 로그인 검증 값을 읽는다.
인증용 값 노출이나 기존 계정 복구 경로까지 해결한 상태로 간주하면 안 된다.
이번 검증은 익명/일반 인증 주체와 허가된 관리자 주체 사이의 본문 접근 경계를 검증한 것이다.
정상 관리자 인증을 탈취한 공격자까지 막는 별도 인증 개편은 포함하지 않았다.

후속 작업은 민감 회원 필드 조회 차단, 로그인/계정 복구 검증의 서버 전환, 관리자 권한 발급 절차,
필요시 기존 인증 수단 재설정 및 단계적 배포다. 현재 사이트 로그인을 갑자기 막지 않도록 별도로 전환해야 한다.

## 검증 근거

독립 PostgreSQL에서 기존 전체 허용 정책을 재현해 제한 정책의 우선 적용, 본문 없는 공개 목록,
직접 조회·연결 조회·조건 검색·시각 변경·분류 변경·프로필 역할 위조를 검증했다.
운영 DB에서도 테스트 트랜잭션을 전부 롤백하며 익명 차단, 관리자 조회·수정, 시작 후 공개를 확인했다.
기존 공지·신청·원본 로그·포인트 기록은 적용 전후 건수와 내용 요약값이 일치했다.

정책 결합과 뷰 권한은 [PostgreSQL 17 정책 문서](https://www.postgresql.org/docs/17/sql-createpolicy.html)를 참고했다.
일정 전용 뷰의 소유자 권한은 안전한 필드만 공개하기 위해 의도적으로 사용한다.
실시간 변경의 이전 행 처리도 [Supabase 실시간 변경 문서](https://supabase.com/docs/guides/realtime/postgres-changes)를 확인했다.

## 로그인 보안 후속 작업

2026-08-31 후속 작업에서 서버 인증 전환 코드를 로컬에 준비하고 가상 계정·독립 DB·브라우저·빌드를 검증했다.
운영 인증 DB 변경과 배포는 아직 하지 않았다. 새 인증 화면만 단독 배포하면 안 된다.
적용 전제, 이용 방식의 차이, 복구 및 검증 범위는 [로그인 보안 전환 메모](account-auth-transition.md)를 따른다.
