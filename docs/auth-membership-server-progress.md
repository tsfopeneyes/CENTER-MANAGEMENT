# 회원 저장·인증 연결 트랜잭션 진행 기록

현재 경험 유지 범위는 `auth-scope-current-experience.md`를 따른다. 새 화면/질문/승인 절차를 추가하지 않았다.

## 추가한 내부 구조

`membershipFinalizer.mjs`는 기존 폼 검증 결과를 사용해 다음을 하나의 DB 트랜잭션으로 저장한다.

1. 비밀번호 없는 일반 회원 행. 현재 신규 가입과 동일하게 Auth ID를 회원 ID로 사용한다.
2. 보호된 회원–Auth 연결. 일반 가입은 active, 기존 만 14세 미만 규칙은 pending.
3. 서버 전용 로그인 식별자. 보호자 승인 대기 상태에서는 비활성.
4. 가입 완료 기록. 동일 요청 재시도/COMMIT 응답 유실 판정에 사용한다.

모든 단계 성공 전에는 가입 완료를 반환하지 않는다. 실패 시 신규 회원·연결·식별자·완료 기록이
함께 롤백된다. Auth 계정을 삭제하거나 기존 회원을 덮어쓰는 보상 처리는 없다.
이미 완료된 요청은 원래 결과만 반환하고 이후 관리자 수정/계정 차단을 되돌리지 않는다.
이 응답은 로그인이나 접근 승인 응답이 아니다.

처리 기록의 요청 비밀값 digest/제출 정보 digest/Auth ID/서버 metadata/현재 실제 세션을 확인한다.
클라이언트가 지정한 회원 ID로 연결하거나 전화번호만으로 기존 회원·게스트를 채택하지 않는다.
기존 전화번호 중복은 거부하고, 신규 완료 기록의 phone key UNIQUE도 중복 완료를 막는다.
이 제약은 전화번호 소유 증명이 아니다. 기존 가입 근거 계약은 여전히 미채택 상태다.

`registrationService.mjs`는 명시적으로 주입된 finalizer가 있을 때만 이를 호출한다.
완료 응답의 상태만 전달하며 내부 ID/토큰은 내보내지 않는다. 없으면 준비 단계 결과만 반환한다.
실제 앱 HTTP 경로/가입 훅과 연결한 것은 아니다.

## SQL 및 권한

`supabase/manual/proposals/auth-membership-foundation.sql`은 격리 시험용 제안이다.
NOLOGIN 전용 worker에 신규 회원 INSERT와 보호 연결 INSERT만 허용하고, 기존 회원 UPDATE/DELETE,
공개 password 열 읽기/쓰기, Auth 수정, 완료 기록 변경/삭제, 세션 신뢰 근거 생성 권한은 주지 않는다.
기존 users RLS가 비활성이면 제안 적용부터 실패한다. 제한적 INSERT 정책으로 password NULL 및
일반 회원 역할을 강제한다. 기존 permissive PUBLIC 정책이 있어도 이 제한을 우회하지 못하도록 했다.
기존 트리거가 비밀번호를 채우면 저장을 거절한다. NOT NULL 등 기존 제약을 임의 변경하지 않는다.

운영 DB에서는 실행하지 않았다. 공개 테이블의 기존 정책/트리거에 영향을 줄 수 있으므로 검토와
실제 격리 환경 검증 전에 적용 금지다. 다른 legacy writer가 동시에 전화번호를 쓰는 경우까지
잠금으로 통제한 것은 아니다. 활성화 전 모든 가입 쓰기 경로의 조정이 필요하다.

## 검증

`node scripts/test-membership-finalizer.mjs` 통과. 메모리 PGlite에서 실제 SQL과 전용 역할로 검증했다.

- 일반 회원/기존 보호자 승인 대기 상태 및 비밀번호 미저장
- 4개 저장 단계 각각의 사후 오류 주입 → 전체 롤백 → 재시도 성공
- 실제 COMMIT 후 응답 유실 → 같은 완료 기록으로 재개, 중복 행 없음
- 재시도로 관리자 이름 수정/차단 상태를 되돌리지 않음
- 전화번호 충돌, 제출 변경, 요청 비밀값 오류, 만료, 세션 폐기, 역할 주입 거절
- 기존 permissive 정책 및 비밀번호 생성 트리거가 있는 상황에서도 저장 차단
- 최소 권한, 연결 반환, 기존 회원 원본 및 원시 로그 내용 보존

Auth 검증은 테스트 대역이며 DB의 실제 세션 행도 확인한다. 실제 Supabase 프로젝트의 SDK,
다중 연결 잠금/부하, 운영 트리거 전체를 검증한 것은 아니다.
`test-registration-service.mjs`는 finalizer 호출 계약/실패 시 세션 정리/응답 최소화도 확인한다.

## 아직 남은 내부 작업

- 실제 회원 스키마·기본값·제약·트리거·기존 정책 확인. 루트 `schema.sql`은 정상 스키마 덤프가
  아니라 CLI 설치 안내 텍스트였으므로 근거로 사용하지 않았다. 기존 훅과 별도 SQL에서 확인한
  필드를 시험 fixture에 사용했다. 운영 호환성을 확인했다고 주장하지 않는다.
- `supabase/manual/membership-schema-preflight.sql`에 회원 원문/비밀번호를 읽지 않는 구조 확인
  SELECT를 준비했다. 실행이나 구조 변경은 하지 않았다.
- 현재 가입 흐름과 준비 서비스의 요청 어댑터 통합. 실험용 enrollment 계약은 운영 요구로 채택하지 않는다.
- 기존 보호자 승인 동작과 private 계정 상태의 원자적 동기화, 게스트 연결의 안전한 호환 처리.
- 실제 로그인/가입 서버 라우팅 및 공통 클라이언트 연결, 전역 권한 검사, 전체 서비스 복구 시험.

운영 변화가 필요한 사항은 기존 별도 기록에 모으고 작업 후 제안한다. 이 작업은 운영 배포나
전체 인증 개편 완료를 의미하지 않는다.
